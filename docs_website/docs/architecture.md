# Internal Architecture

Mamba is not interpreted; it is a full language compiler. 

## The Compilation Pipeline

When you run `./mamba build app.mb --release`, Mamba goes through several stages:

```text
Mamba Source Code (*.mb)
         ↓
    Preprocessor (Resolves imports, merges files)
         ↓
    Parser (Lark LALR Grammar Parser)
         ↓
    AST (Abstract Syntax Tree)
         ↓
    Target Generator (e.g., C++20)
         ↓
    clang++ (Native Compilation with -O3 flag)
         ↓
    Standalone Executable (Native Binary)
```

### Compiler Modules Reference
- **`preprocessor.py`**: Handles `#import` or `import "file.mb"` directives.
- **`builder.py`**: The core driver orchestrating AST parsing and code generation.
- **`targets/cpp.py`**: Emits highly-optimized C++ source code.
- **`targets/php.py`**: Emits PHP script representations.

## Native Web Server Architecture

The C++ executable generated by Mamba embeds a custom POSIX socket HTTP server.

```text
Incoming Connection
       ↓
     Socket
       ↓
   HTTP Parser
       ↓
  Request Object
       ↓
   Worker Queue
       ↓
 20 Worker Threads (std::thread pool)
       ↓
   Mamba Route
       ↓
    Response
```

### Key Performance Attributes
- **Thread Pool:** Automatically scales to hardware concurrency limits to process requests simultaneously.
- **CORS Handling:** Natively responds to `OPTIONS` preflight checks.
- **Thread Safety:** Integrates SQLite `std::mutex` locking behind the scenes to ensure database operations are safe under extreme concurrent load.
